## [美国将意大利托管商 Autistici/Inventati 列为恐怖实体](https://www.inventati.org/) ⭐️ 9.0/10

美国国务院和财政部将总部位于意大利的 Autistici/Inventati（A/I）集体列为“特别指定全球恐怖分子”，该组织运营匿名博客平台 noblogs.org。这标志着美国首次将互联网基础设施提供商作为恐怖实体进行制裁。 制裁基础设施提供商开创了一个危险的先例：它表明美国可以认定任何科技集体、隐私工具或托管平台为恐怖实体，只要其认为这些平台为激进组织服务。这可能会压制注重隐私的服务、代理服务和去中心化平台的运营，影响全球的开发者和用户。 美国国务院声称，A/I“专门向激进左翼行动者提供工具和服务”，并对用户进行意识形态审查，称其是“暴力犯罪极左网络”中的关键节点。A/I 自 2001 年由意大利活动人士创建，提供免费通信工具、电子邮件和博客服务，包括基于 WordPress 的匿名博客平台 NoBlogs（noblogs.org）。

hackernews · exiguus · 8月28日 12:58 · [社区讨论](https://news.ycombinator.com/item?id=49477854)

**背景**: Autistici/Inventati（A/I）是 2001 年由意大利自主反资本主义运动中的个人和集体创建的组织，旨在提供免费、尊重隐私的通信工具。“特别指定全球恐怖分子”（SDGT）认定会冻结与美国相关的资产，并禁止美国人与该实体进行交易，且可能通过金融中介机构产生连锁反应。

## [ZBT 路由器出厂内置两个后门，允许未认证攻击者获取根权限](https://thehackernews.com/2026/08/china-made-zbt-routers-ship-with-two.html) ⭐️ 9.0/10

VulnCheck 披露了 ZBT 路由器固件中两个未记录的出厂植入后门，编号为 CVE-2026-74232（SPEAKINGSTONE）和 CVE-2026-74233（DARKLANTERN），二者均允许未认证的远程攻击者以 root 权限执行命令。 这是一个严重的供应链安全问题，因为这些植入物在出厂时即存在，可能影响大量已部署设备。任何处于网络或互联网上的未认证攻击者都能完全控制路由器，从而进行监控、流量劫持或将其用作僵尸网络节点。 DARKLANTERN 在 WAN 接口的 UDP 9992 端口上监听并无需认证地接受命令；其校验和使用了硬编码盐值"mqonu.com"，且 MAC 过滤器可通过全零 MAC 地址绕过。SPEAKINGSTONE 会回连 ZBT 的云基础设施，并带有一个未注册的硬编码备用 C2 域名；研究发现约有 203 个暴露于互联网的主机受 DARKLANTERN 影响。

rss · The Hacker News · 8月28日 10:58

**背景**: ZBT（深圳市智博通电子）是一家中国路由器制造商，其固件被广泛应用于全球许多低价路由器中。这些工厂植入物与此前发现的 ENDLESSDOORS 植入物相互独立，意味着 ZBT 固件中至少存在三个不同的后门。这些植入物看起来是有意的供应链后门，而非偶然缺陷，使制造商（或第三方）能够持久远程访问设备。

## [仅凭漏洞传闻即可快速制造可利用漏洞](https://anil.recoil.org/notes/rumour-is-the-exploit) ⭐️ 8.0/10

一篇评论文章指出，如今仅凭软件漏洞的传闻，就能比以前快得多地转化为实际可利用的漏洞，尤其是在 AI 的辅助下。作者认为这一动态正在改变维护者和用户所面临的安全格局。 此事意义重大，因为它改变了漏洞利用的成本效益平衡，给面临海量安全披露的开源维护者带来了更大压力。它也凸显出 AI 正在使漏洞利用开发变得大众化，可能导致对低价值目标的大规模攻击。 文中引用了真实维护者的经历：一位维护者报告说，过去一个月收到 40 多份安全披露，而项目前十年总共才收到约 20 份。虽然会使用 AI 工具进行分诊和修复，但约 75%的披露中仍有需要关注的“关键点”。

hackernews · avsm · 8月28日 15:58 · [社区讨论](https://news.ycombinator.com/item?id=49480466)

**背景**: 安全披露是指通过 GitHub 等平台提交的软件潜在漏洞正式报告。传统上，漏洞利用开发者会研究补丁差异、提交信息或随口提及的评论来构造可利用漏洞。大语言模型（LLM）降低了技能门槛，使更多参与者能将零散信息快速转化为代码，而开源维护者往往缺乏资源应对突然激增的披露。

**社区讨论**: 评论者们大体赞同这篇文章，维护者描述了披露量过载的情况，并对 AI 的作用抱有复杂情绪。有人认为真正的问题是缺乏快速修复漏洞的意愿，也有人担心修复成本降低会让普通公民的低水平黑客行为变得过于昂贵。少数人指出这种做法并不新鲜，但已被 LLM 民主化和规模化，还有人因此建议将仓库设为私有。

OpenAI 官方 Python SDK 正在迁移到 HTTPX2——这是由 Pydantic 维护的 httpx 稳定分支，旨在避开 httpx 1.0 版本即将带来的破坏性变更。Anthropic 的 SDK 也在其后不久做出了同样的切换。 这件事很重要，因为 OpenAI 和 Anthropic 是两个使用最广泛的 Python SDK，它们对 HTTP 客户端的选择会影响整个生态。这也表明 API 稳定性是库维护者的优先考虑，用户可以因此减少依赖损坏的问题。 HTTPX2 是 httpx 0.28.1 的分支，公共 API 相同，因此对开发者来说迁移几乎是无缝的。一个值得注意的行为变化是，HTTPX2 现在使用操作系统的 TLS 信任库而不是 certifi，这可能影响证书验证的方式。

hackernews · tosh · 8月28日 11:51 · [社区讨论](https://news.ycombinator.com/item?id=49477212)

**背景**: httpx 是一个流行的 Python HTTP 客户端，提供同步和异步 API，并支持 HTTP/1.1 和 HTTP/2。httpx 项目正在向 1.0 版本推进，该版本将包含破坏性变更，对依赖它的库来说有风险。HTTPX2 作为一个承诺不破坏现有 API 的分支而创建，为依赖库提供了稳定基础。
